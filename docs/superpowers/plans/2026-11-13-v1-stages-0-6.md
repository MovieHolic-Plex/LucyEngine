# AI 게임 에디터 v1 (0~6단계) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한두 문장을 입력하면 새로 생성된 에셋으로 된, 걸어 다니고 대화하고 싸울 수 있는 Eastward 톤 장면 하나가 나오는 웹 에디터를 만든다.

**Architecture:** 프로젝트 문서(JSON)가 유일한 정본이고 명령 계층이 유일한 변경 통로다. 시뮬레이션은 Phaser 와 무관한 순수 TypeScript 로 만들어 Node 에서 그대로 돌리고, Phaser 는 그리기와 입력만 맡는다. 서버가 문서의 권위 있는 사본과 에이전트를 갖고, 브라우저는 WebSocket 으로 변경을 주고받는다.

**Tech Stack:** pnpm 워크스페이스, TypeScript, Vite, Vitest, React, zustand, zod, Phaser, Fastify + WebSocket, Node 내장 `node:sqlite`, sharp, `@anthropic-ai/sdk`, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-13-ai-game-editor-design.md`

**이 계획의 형식에 대해:** 사용자가 자리에 없는 동안 0~6단계를 한 번에 진행하라는 지시에 따라, 단계별 계획을 따로 쓰는 대신 한 문서에 묶었다. 작업마다 파일·인터페이스·검증 방법을 적되 구현 코드 전문은 싣지 않는다. 인터페이스의 최종 정본은 `packages/model/src` 의 타입이다.

## Global Constraints

- 코드는 사용자에게 어디에도 노출하지 않는다.
- 프로젝트 문서를 바꾸는 코드는 반드시 `model` 의 `applyCommand` 를 거친다. 다른 패키지가 문서를 직접 고치지 않는다.
- 모든 명령은 역명령을 돌려주고, "적용 후 역명령 = 원본" 테스트가 있다.
- `model` 은 다른 워크스페이스 패키지와 DOM·Node API 에 의존하지 않는다.
- 시뮬레이션(`runtime/src/sim`)은 Phaser·DOM 을 import 하지 않는다.
- DB 는 서버의 SQLite 파일 하나다. 에셋 이미지는 내용 해시 이름으로 디스크에 둔다.
- Eastward 원본 그림을 생성 입력으로 쓰지 않는다. 생성 프롬프트에 작품 이름을 쓰지 않는다.
- UI 문구는 한국어다. 시각 언어는 애플 프로 앱 방향(반투명 재질, 넉넉한 여백, 시스템 서체 + Pretendard, 스프링 애니메이션, 시스템 라이트/다크 추종)이다.
- API 키와 모델 주소는 서버 환경 변수로만 받는다 (`ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `AGENT_MODEL`, `IMAGE_API_BASE`, `IMAGE_API_KEY`, `IMAGE_MODEL`).
- 커밋 메시지는 한국어, 논리 단위로 나눈다.

## 결과와 남은 문제 (2026-11-13)

0~6단계를 한 번 끝까지 만들었다. 사용자가 자는 동안 혼자 판단해 진행했으므로, 판단이 들어간 곳은 아래에 근거와 함께 적는다.

### 측정

- **v1 성공 기준 (5.4)**: 빈 프로젝트에서 "비 갠 저녁, 버려진 기차역 앞 작은 광장. 매표소 영감이 말을 걸고, 풀숲에는 슬라임 두 마리가 있어." 한 문장 → **216초** 만에 새로 생성한 그림 20장(재질 5, 소품·건물 12, 인물 2, 적 1)으로 된 장면. 조명·후처리, 주인공 이동, 선택지 있는 대화, 슬라임 전투까지 실제 브라우저(Playwright)에서 확인. 시간의 대부분(약 140초)은 그림 생성이며 분당 10장 제한이 병목이다. (`scripts/e2e-scene.mjs`) 같은 방식으로 "안개 낀 숲속 야영지" 270초, "사막 오아시스 장터" 202초.
- **평가 (6.3)**: 고정 요청 6개를 내장 키트로 돌려 5/6 통과, 요청당 44~96초. 실패한 `mine` 은 광부와 대화해야 길이 열리는 장면을 AI 가 일부러 만들었는데, 채점기의 전투 시험이 대화 없이 바로 싸우러 가서 막힌 경우다. 채점기의 한계로 본다.
- **손 편집 (3.7, 6.4)**: `pnpm e2e` 5개 통과 — 고르기·이름 고치기·끌어 옮기기·되돌리기·다시 하기·새로고침 후 유지, 복제·지우기·붓질(붓질 한 번이 히스토리 한 칸), 플레이 진입과 이동과 복귀(플레이가 문서를 바꾸지 않음), 팔레트로 분위기 바꾸기, AI 요청 → 변경 카드 전/후 그림 → 카드에서 되돌리기.
- **그림 생성까지 한 평가**: `pnpm eval --generate --only harbor` 통과, **445초**. 같은 분당 10장 제한 아래에서도 프록시 쪽 재시도·대기에 따라 3~8분으로 흔들린다.
- 비용은 토큰으로만 기록한다(프록시가 가격을 주지 않는다). 새 장면 한 번에 출력 약 6천 토큰, 캐시 읽기 약 8만 토큰, 그림 약 20장.

### 스펙과 달라진 점

- **헤드리스 플레이테스트는 서버에서 순수 시뮬레이션으로 돈다.** 스펙은 브라우저에서 돈다고 했으나, 시뮬레이션을 Phaser 와 떼어 놓았으므로 서버에서 돌리는 편이 빠르고 편집기가 닫혀 있어도 된다.
- **AI 의 "보기"(스크린샷)는 편집기에 숨겨 둔 두 번째 화면이 찍는다.** 사용자가 보는 화면의 카메라를 건드리지 않기 위해서다. 편집기가 하나도 열려 있지 않으면 AI 는 보지 못하고 요약·점검·플레이테스트만 쓴다.
- **계획을 단계별 상세 문서 대신 한 장으로 줄였다.** 사용자가 자는 동안 끝까지 가는 것이 목표였다.
- **"처음 온 사람" 시험(6단계)은 자동 E2E 로 대신했다.** 사람으로 하는 시험은 아직 하지 않았다.
- **팔레트 교체는 "색 돌리기" 도구(`recolor`)로 했다.** 색상각·채도·밝기를 돌린 뒤 프로젝트 팔레트에 다시 맞춘다. 원본을 두고 색만 다른 변종 프리팹도 만들 수 있다(빨간 슬라임 등).
- **제품 이름은 처음에 작업 이름 "Atelier" 를 임시로 붙였다가, 사용자가 LucyEngine 으로 정했다.**

### 남은 문제

- 생성한 바닥 무늬가 어둡고 잔무늬가 많아 반복이 눈에 띌 때가 있다(내장 키트 재질보다 못하다). 에이전트 도구 설명에 "바닥은 표면만 짧게 묘사"를 넣었지만 근본적으로는 재질 후처리(대비 낮추기, 큰 무늬 지우기)를 더 손봐야 한다.
- 에셋 생성이 분당 10장 제한에 묶여 새 장면 하나가 3~4분 걸린다. 같은 프로젝트의 그림을 다시 쓰거나, 장면에 꼭 필요한 것부터 먼저 그려 보이는 순서 조정이 다음 개선 후보다.
- 평가 채점기의 전투 시험은 대화·이벤트로 열리는 길을 모른다(`mine` 실패).
- 여러 사람이 같은 프로젝트를 동시에 손으로 고치면, 늦게 도착한 편집이 앞 편집과 부딪힐 때 그 사람 화면을 통째로 다시 맞춘다(편집은 잃지 않지만 매끄럽지 않다). v1 은 한 사람 사용을 가정한다.
- AI 가 작업하는 동안에는 손 편집과 되돌리기를 막는다. 턴은 멈춤 버튼으로 언제든 끝낼 수 있고, 그러면 아무것도 바뀌지 않는다.
- 서버가 턴 도중 다시 시작되면 그 턴은 버려지고 채팅에 그렇게 표시된다.
- 개발 중 두 번, 페이지를 연 직후 그림이 모두 임시 상자로 보인 적이 있다. 원인은 재현하지 못했다(개발 서버 재시작과 겹친 것으로 추정). 실패한 그림을 간격을 늘려 가며 계속 다시 받도록 고쳤다.
- 편집기 번들이 크다(Phaser 포함 1.8MB, gzip 490KB). 코드 분할은 하지 않았다.
- 모바일·터치 편집은 다루지 않았다.
