# 0단계 에셋 스파이크 결과

- 날짜: 2026-11-13
- 비교 페이지: 내부 서버에 게시했다 (저장소에는 없다). 다시 만들려면 `spike/build-page.py`.
- 판정: 사용자가 자리에 없어 Claude 가 판정했다. 근거 그림은 비교 페이지에 있다.

## 질문

한두 문장 요청으로 한 장면 분량(지형 재질 3, 소품 8, 건물 2, 주인공·NPC·적 2종)을 일관된 톤으로 뽑을 수 있는가.

## 결론

뽑을 수 있다. **방식 (가): 이미지 모델에 글로만 요청하고, 결정적 후처리로 게임 에셋으로 만든다.**

| 방식 | 결과 |
|---|---|
| (가) 이미지 모델 + 후처리 | 채택. 같은 요청 3회 모두 17장 전부 쓸 만했다 |
| (나) 언어 모델이 화소 격자를 직접 씀 | 탈락. 단순하고 느리며(장당 평균 53초), 큰 그림은 줄 길이가 틀어진다 |
| (다) (가) + 스타일 기준 그림 | 탈락. 8개 소품 중 2개에 기준 그림의 대상이 섞여 들어왔다 |

## 통과 기준별 판정 (방식 가)

| 기준 | 판정 | 근거 |
|---|---|---|
| 팔레트·화소 밀도·시점 일치 | 통과 | 모든 그림이 같은 팔레트(21계열 × 7단계)와 같은 축척으로 줄어든다. 시점은 프롬프트의 정면 고정 문구로 맞춘다 |
| 타일 이음새가 보이지 않음 | 통과 | 가장자리 띠에서 반대편 화소를 확률적으로 섞어 이음새를 없앤다. 넓은 색 얼룩을 걷어내 반복도 줄였다 |
| 걷기 애니메이션이 깜빡임 없이 읽힘 | 통과 | 서 있는 그림에서 다리만 움직여 프레임을 만들므로 몸통이 프레임마다 같다 |
| 같은 요청 3회 중 2회 이상 쓸 만함 | 통과 | 3회 중 3회. 세 번째 실행에서 집이 살짝 비스듬하게 나온 것이 유일한 흠 |
| 장면 하나 5분 이내 | 통과 | 104~116초 |
| 비용 | 측정만 | 그림 한 장에 출력 약 1,500토큰, 한 장면 17장에 약 2.6만 토큰. 쓰는 프록시가 단가를 알려 주지 않아 금액으로 환산하지 않았다 |

## 이 결과로 확정한 것

- **타일 한 칸 24화소, 기준 화면 640×360.** 스펙 초안의 16화소에서 바꿨다. 생성 그림을 줄일 때 디테일이 살아남는 크기다. 사람 캐릭터는 높이 38화소.
- **Phaser 4.2.1.**
- **조명:** 화면 크기 렌더 텍스처에 주변광을 칠하고 점광원을 더하기로 찍은 뒤 장면 위에 곱하기로 얹는다. 그 위에 광원마다 빛 번짐을 더하고, 카메라 필터로 색 보정·블룸(임계값 + 흐림을 더하기로 합성)·비네트를 건다.
- **그림자:** 스프라이트 윤곽을 오른쪽 아래로 기울여 만든다 (빛은 왼쪽 위).
- **건물은 통그림 한 장.** 부품 시트는 칸 크기와 이음이 고르지 않아 v1 에서 쓰지 않는다.
- **사람 캐릭터는 세 방향(앞·옆·뒤) 그림 한 장 + 코드로 만든 걷기 프레임.** 이미지 모델이 그린 걷기 시트는 더 풍부하지만 방향 간 디자인 불일치 위험과 추가 비용이 있어 다음 버전 후보로 둔다.
- **다리 없는 생물은 한 방향 그림 + 좌우 반전 + 통통 튀는 프레임.**
- **이미지 모델 한도:** 분당 10장 안팎에서 걸리고 1~2분 뒤 풀린다. 생성기는 분당 10장으로 줄을 세우고, 걸리면 기다렸다 다시 시도한다.
- **배경 제거:** 마젠타 단색 배경을 요청하고 색상각으로 지운다. 보라·분홍이 주색인 대상은 배경과 헷갈릴 수 있다 (알려진 한계).

